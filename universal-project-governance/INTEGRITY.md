# Skill Integrity Protection

## Purpose

Protect the governance protocol itself from accidental modification during normal project work.

## Protected Areas

The following categories require explicit authorization before modification:

- Skill entry instructions;
- core governance principles;
- validation policies;
- release criteria;
- integrity rules.

## Required Change Process

A governance protocol modification requires:

1. user authorization;
2. documented reason;
3. version impact analysis;
4. changelog update;
5. integrity validation;
6. release evidence refresh.

## Principle

The Skill may govern projects, but it must also govern its own evolution.

Integrity protection prevents silent degradation where an agent weakens rules while performing unrelated work.
