# 离线演化协议

当前可执行协议是 [upg-evolution-v2.json](upg-evolution-v2.json)，供 `python -m evolution run` 和 `ablate` 使用。它定义开发预算、搜索模块、历史比较基线和独立证据准入阈值；运行时治理规则仍以 [governance-src](../../governance-src/README.md) 为准。

每个新实验必须先冻结自己的任务、模型、回调、执行源码、配置、顺序和预算。现有协议是开发入口，不是模型调用授权，也不是已完成测量。历史实验注册已从当前树移除；恢复与复核使用 Git 基线 `dc907ea`，不把旧结果当作当前候选验收。

当前运行入口、各模块职责、信任边界和检查命令见[离线演化说明](../../docs/offline-evolution.md)。

独立准入由 [promotion.py](../promotion.py) 重新计算，至少要求：

- 候选选择、独立 holdout 冻结和实际观察按 Git 锚点及带时区时间排序；`run_id`、候选、协议、源码、引擎、基线和评分器身份完整匹配。
- 非空且不同的优化者与独立评估者身份；训练、选择和最终 split 的任务、项目、族隔离；已暴露最终任务不得再次作为独立 holdout。
- 每次失败、重试、学习、排名与任务调用都有实际 provider 收据。收据对象、请求唯一性、完整用量、非负有限费用、真实耗时和正向产物评分均需核验。缓存复用不增加样本。
- 引用是 `{path, sha256}`，路径必须指向当前证据根目录内的有界普通 JSON 对象文件；哈希校验不证明 provider 或评分器诚实。
- 完整的配对条件、族覆盖、固定权重、bootstrap、质量和硬性安全约束、预算与收益门禁。缺失、未知、失败或不完整证据不得变成通过。

`verify` 分别报告工程、实证与正式资格状态；`propose` 仅在独立门禁通过后原子发布可评审提案，不修改规范源码或授予资格。
