# 上游概念的选择性映射

[上游来源表](../third_party/upstream-sources.json) 是已审阅 commit、文件、许可身份、选用概念、排除行为、UPG 目标、触发和 UPM 验收契约的唯一登记入口。[公开致谢](../THIRD_PARTY_NOTICES.md) 与[既有许可和历史记录](../third_party/notices/README.md)继续保留。

映射记录独立的概念适配，不是运行时规则源。治理语义仍以 `governance-src/model/governance-model.json` 为准；运行时由它编译，不拼接外部 Skill。阅读外部 Skill 不会激活其角色，也不授权工具、网络、凭据访问或安装。

每个 `sources[].selected_files` 条目保留固定 commit 链接和 Git blob 身份；`mappings[]` 将已审阅的文件/章节关联到既有 policy、可选 execution-guidance ID、具体触发和一个验收用例。排除项说明其与完整责任层修改、事实精度、有界证据或用户指令冲突的部分。当前许可与历史/传递性声明分别保留；致谢不代表背书或许可使用无关资产。

## 当前语义承接

既有四条 execution guidance 的完整表达只在 Skill 中渲染一次；计划保留原基础 policy closure，按需附加模型中的工作流块。计划必须配合已加载 Skill 使用；无 helper 时使用 Skill 与手工 index 路由。工作流迁移不删除 start facts、因果顺序、latest/previous、真实字节回执、未知、验证、清理或交接义务，见[源码职责](../governance-src/README.md#任务投影)。

UPM 用例定义正例与失败条件。`test_references` 是验证入口，不表示新运行已通过；发布审计必须绑定实际执行结果和被测源码。空引用需要补充 fixture 覆盖或明确评审。来源哈希、公开致谢和静态验收都不证明模型质量、token/时间节省、因果收益或正式资格。

## 比较与证据边界

来源消融只移除预注册的新增 execution guidance；核心 policy、既有工作流、真实证据、安全、必要验证和交接义务仍必须保留。前瞻协议须严格绑定当前编译产物；调用失败、费用未知和执行身份缺失都必须保留，不能重放未知调用或将未知费用算零。

提供方报告的模型名和 usage 不证明内部模型身份或全部重试覆盖。不同 tokenizer 的绝对 token 数、API 与 CLI 延时不能直接合并成因果效果；字节计量也不是 token 测量。已暴露的开发目标不能重新称为独立留出任务，失败或无收益结果不授权晋升。

## pstack 工作流适配

本次审阅固定在 [cursor/plugins 的 pstack 子树](https://github.com/cursor/plugins/tree/8b3326d99fd4b993cb33a24dad8af03175c642c5/pstack)，插件声明版本为 0.15.30。完整目录处置保存在来源表的 `pstack.inventory`：57 个顶层 Skill、23 个 playbook、2 个 agent，另列 3 个 Benny 自动化内部 Skill。每项保留固定路径、Git blob、字节数、处置、承接 policy 和适用限制。目录范围/步骤审阅与 `selected_files` 中实质适配章节的审阅分开记录。没有安装、执行或拼接上游脚本、角色与完整提示词。

UPM-011 将明确结果、理解当前行为与契约、确定责任层和数据所有权、按可验证单元实施、清理并证明结果吸收到既有 policy 和按任务选择的 `engineering_workflow`。错误修复选择有意义的前后证据，重构保持已知行为；反复失败时检验共同前提；并行任务明确写入所有权。只有实际任务需要时才比较设计、构建验证工具、分析性能或使用模型检查，不设置模型、候选、验证通道或提交数量配额。

UPM-012 要求每次修改维护内容后的正常完成都审查与审计受影响的最终状态，包括局部低风险与无报告工作。核对意图、正确性、错误与安全边界、真实消费者、结构责任、重复/废弃代码、过时文档、生成漂移和验证证据。发现项须有实际路径或相称证据，负责人判断并处理；范围内阻塞项未解决时不得正常完成。后续改动使相关审查和验证过期，必须重新核对。可用 helper 对其跟踪的完成边界校验有界审查证据；没有 helper 时仍执行完整 Skill 义务，不能声称机械强制已覆盖。风险较高时按实际能力安排独立审阅，缺少独立性必须明示。共识、路径、摘要和哈希都不证明语义正确。

UPM-013 承接真实产物/用户路径证明、受影响验证说明和模型的维护、失败反例、等价性及测量真实性。复用现有启动、驱动、观察和清理入口；区分文档漂移、验证工具缺口、模型漂移和产品缺陷；只清理本次拥有的进程与临时状态，保留实际证据。形式验证保留模型假设和边界，性能结论保留正确工作量、错误和可比条件，未知或未证实仍保持未知。

UPM-014 补足任务开始与进行的完整责任链。先依据用户实际要求明确可验证结果、范围和保留约束，再调查当前入口、规范状态、实际数据流与消费者、已有验证、关键未知和可用能力。研究从具体问题和源码锚点出发，只读取相关且已授权的证据；可观测的分歧选择相称的只读检查或隔离试验，不把可自行验证的问题转交用户，也不替用户决定产品偏好或越过权限门槛。来源表区分已通读的适配章节与目录范围审阅，不因目录或哈希存在便宣称真实调查已发生。

非平凡任务在修改前把必要单元、依赖、先决条件、写入所有者、产物及通过判据放进既有工作流或其引用的当前项目状态。风险未知优先，复用现成工具与验证入口；局部低风险修改可只有一个单元。每个单元按实际目标或假设执行，并核对当前产物和观察结果；失败、未验证或不确定的前置项不能作为依赖已满足。大批相似改动先用首个真实单元检验任务说明、验证配方与单元大小，再按实际需要扩展并行，不要求额外试验机器、固定通道或专职评审。

进行中的检查发生在当前授权会话和阶段边界，依据产物、当前修订与验证判断进度；每个委派范围都要有结果、明确接管或覆盖缺口。晚到结果先与当前范围、修订和已接受产物对账。新约束、新消费者、失败前提、失效证据或工具边界触发有原因的重规划，仅修改受影响的余下计划并复核相应依赖；保留开始事实、失败记录和仍有效的证据，不通过放宽验收、补造前置成功或覆盖历史来完成任务。系统性验证或环境失败先停止依赖它的工作，其他独立且已授权工作仍可继续；不确定业务写入先核对状态，不能盲目重试。

阶段结果、决策、阻塞、下一动作和交接复用现有 `active_workflow`、`current_state`、稳定检查点及有界报告，不新增第二份计划/历史账本。只有真实且必要的单元与原任务验收闭合后才进入 UPM-012 的最终审查与审计。生命周期助手约束有界记录、依赖和证据的一致性；字段齐全、路径/哈希、聊天时间戳和自报完成都不证明语义正确或实际执行。无 helper 时仍遵循完整 Skill 义务，明确机械强制的缺口。历史完成记录不补造计划，原报告开关与未完成恢复边界继续保留。

`orchestrate` 仅条件吸收首单元验证、依赖与结果对账、真实进度判断和有界恢复；其 `orch` 运行时、存储/锁/账本、固定时限与重试次数、云端放置、模型切换、后台观察器、自动合入与权限授予仍排除。相关验证入口为[任务生命周期](../tests/test_task_lifecycle.py)、[路由](../tests/test_pstack_workflow.py)与[来源契约](../tests/test_upstream_sources.py)；链接和静态用例表示验收契约，实际通过结果必须另由当前运行证据确认。

不吸收 Cursor 专属模型表、全局配置、后台观察器、常驻编排、Benny 自动化、外部发信权限、自动合并/推送、强制重置/清理、歧义即删注释、固定报告和文风模板。保留 UPG 的授权、兼容、数据保留、安全、事实精度和任务边界。既有结构化状态与交接继续承接证据，不新增第二账本，也不由局部审查推导全项目无债务。
