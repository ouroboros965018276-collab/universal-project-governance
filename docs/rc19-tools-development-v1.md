## Observed failure and evidence integrity

All eight CLI processes exited with code zero and emitted a known completed-turn
usage record. Each final response truthfully declared `validation: failed`.
Each raw stream contained a Code Mode host-disabled error; each also contained
an experimental `skip_host_skill_discovery` warning. There were 16 error items
in total. The host-disabled messages establish that this configured CLI profile
did not make the bounded tools usable. They do not establish that the registered
repository tasks or candidate instructions caused the failure.

All eight independent broker journals were empty. Every repository retained its
initial bytes. Independent inspection of the JSON, TOML, Python AST and text
contracts confirmed 0/16 positive checks. CLI exit status and successful unit
tests therefore did not become task-success evidence.

The eight raw receipt identities and eight CLI thread identities were distinct.
Every referenced raw-artifact hash, canonical result digest, exact prompt,
condition/engine binding and final-file digest matched. All raw call directories
were referenced once. The eight actual usage records reconciled to the shared
budget with no duplicate charge, cached observation or unknown usage. Collection
ended with no pending call, active dispatch lock or unknown-call fence.

The displayed treatment/control cost ratios, 0.883196 for tokens and 0.840666
for full callback time, describe failed tasks only. They cannot establish useful
savings. The task-quality gate and net-benefit gate are `FAIL`; independent
evaluation and promotion were not authorized by this result. A corrected host
profile requires a separately frozen round. This failed round is not replayed
or relabeled as a successful tool experiment.
